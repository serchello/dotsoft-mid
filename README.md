# DotSoft — динамическая страница услуги (React + Vite)

Общий шаблон страницы, который тянет данные с эндпоинтов вида
`https://dotsoft.gr/wp-json/allposts/v1/{type}/{id}`
(например `.../service/30001` — EcoCorner) и рендерит их в виде страницы товара/услуги,
похожей на оригинал с dotsoft.gr.

## Запуск

```bash
npm install
npm run dev
```

Откройте `http://localhost:5173/service/30001`.

## Как это устроено

- `src/api/dotsoft.js` — fetch к API + **парсер** «грязного» WordPress-HTML из поля `content`
  (там внутри одной строки перемешаны текст, картинки, YouTube-iframe, PDF-ссылка,
  список похожих услуг и две формы Contact Form 7 — всё это разложено на части через `DOMParser`).
- `src/pages/ServicePage.jsx` — грузит пост по `type/id` из URL и собирает страницу из компонентов.
- `src/components/*` — Hero, галерея, текст+сайдбар, лента похожих услуг, своя контакт-форма,
  плюс фирменный элемент `PulseDivider` (анимированная «сигнальная» линия — отсылка к тому,
  что каждая услуга dotsoft.gr — это, по сути, система датчиков/IoT).

## ⚠️ Главное, на что стоит обратить внимание (фидбек по идее)

1. **CORS.** Я проверил: `wp-json/allposts/v1/...` — это обычный WordPress REST API.
   Такие эндпоинты почти никогда не отдают `Access-Control-Allow-Origin`, если это явно
   не настроено на сервере (плагин или `add_action('rest_api_init', ...)`).
   Значит, **прямой fetch из браузера на другом домене (ваш будущий прод-домен) скорее всего
   упрётся в CORS-ошибку**, даже если в dev у вас всё сработает через прокси Vite.
   Варианты:
   - попросить бэкенд-команду dotsoft.gr добавить CORS-заголовки для этого namespace;
   - поставить свой лёгкий серверный прокси (Node/Cloudflare Worker/Vercel Edge Function),
     который сам обращается к dotsoft.gr и отдаёт JSON вашему фронту — самый надёжный путь для прод;
   - в крайнем случае — публичный CORS-proxy, но это небезопасно и нестабильно для продакшена.

2. **`content` — это HTML, а не структурированные данные.** В нём одновременно лежат:
   текст описания, `<figure><img>` галерея, YouTube `<iframe>`, ссылка на PDF, `<ul>` с похожими
   услугами (внутри `<h5><a><img>`) и целых 2 формы Contact Form 7 (действие которых указывает
   на `/wp-admin/admin-ajax.php` **самого dotsoft.gr**, то есть отправка форм с чужого фронтенда
   работать не будет "из коробки"). Я это распарсил через `DOMParser` и разложил на отдельные секции,
   а формы убрал — сделал свой React-компонент `ContactForm`, который надо будет подключить
   к реальному эндпоинту приёма лидов (свой backend или сервис форм типа Formspree).
   Это самое хрупкое место: если верстка контента в WP поменяется, парсер тоже надо будет поправить.
   Более надёжный долгосрочный вариант — попросить добавить в API отдельные поля
   (`gallery: []`, `video_url`, `pdf_url`, `related_services: []`) вместо того, чтобы выковыривать
   их из HTML.

3. **`meta.background` не содержит реального цвета** (в примере EcoCorner там просто `["EcoCorner"]`),
   хотя, судя по дизайну других услуг на сайте, у каждой явно есть свой акцентный цвет/логотип.
   Сейчас акцент захардкожен (`#5be7a9`). Если хотите, чтобы страница красилась в фирменный цвет
   каждой услуги автоматически — нужно либо получить hex из API, либо завести у себя карту
   `slug -> accent color` вручную.

4. **Изображения/лого раздаются с `new.dotsoft.gr`**, а не с основного домена — стоит уточнить,
   стабилен ли этот поддомен, или это временный staging-URL.

5. **Санитизация HTML.** Контент рендерится через `dangerouslySetInnerHTML`. Источник (dotsoft.gr)
   доверенный, но если в будущем контент может редактироваться менее доверенными людьми —
   добавьте `DOMPurify.sanitize()` перед рендером.

6. **SEO/производительность.** Сейчас всё на клиентском fetch (SPA). Если страницы услуг должны
   индексироваться в Google — стоит рассмотреть SSR/SSG (Next.js, Astro) вместо чистого Vite SPA,
   особенно если это публичные лендинги услуг, а не внутренняя админка.

## Что можно добавить дальше

- Кэширование ответов API (react-query/SWR) — сейчас каждый переход делает новый fetch.
- Список всех услуг (нужен отдельный endpoint вида `.../service` без id, либо `?per_page=...`).
- Хлебные крошки / категории (`terms['service-category']`) как отдельная секция-фильтр.
- Локализация (сайт мультиязычный — EN/EL судя по `_wpcf7_locale: en_US` в форме).
